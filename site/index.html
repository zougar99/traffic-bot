Capabilities

A full traffic lab, not a black box

Every layer is configurable and observable — from the proxy pool to the click pattern on a search result page. Nothing runs you can’t inspect.

Proxy rotation engine

HTTP, HTTPS and SOCKS5 pools with round-robin selection, per-session assignment, folder-based proxy files and automatic fallback when a node dies.

Stealth layer

Navigator patches, WebGL / Canvas / Audio fingerprint spoofing and randomized Chrome launch arguments to keep sessions consistent with a real device.

Human-like behavior

Variable typing cadence, natural scroll curves, dwell time before engagement and configurable pauses between sessions — tuned per profile.

Search-engine modes

Google, Bing, Yahoo and DuckDuckGo paths: type a keyword, parse the SERP, locate your domain and click through like an organic visitor.

Engagement toolkit

Optional like and comment actions with a comment library in comments/, plus rotating email identities loaded from email/.

Telegram control

Run and stop campaigns from your phone with /run and /stop, check pool size with /status, and receive start / done / error reports.

Session visibility

Watch browsers run in GUI mode or go headless for background batches. Live console logs show proxy, email and mode for every session.

Campaign batching

Queue multiple target URLs and a session count per URL. The runner interleaves URLs across rounds so traffic never looks machine-shaped.

local-first

Runs on your machine

No SaaS account, no shared dashboard, no data leaving your device. Electron app, MIT-licensed source, your proxies and your rules.

Operating modes

Three ways to reach a page

Pick the path that matches the signal you’re testing. Each mode has its own session flow, timing controls and engagement hooks.

Direct navigation

The fastest signal. The bot picks the next proxy from your pool, launches a stealth browser and lands on the target URL with realistic dwell time, scrolling and optional engagement.

  • Round-robin proxy assignment per session index
  • Configurable delay after load before any action
  • Best mode for analytics hit validation

Search-engine path

The full organic journey. A keyword is typed at human speed, the result page is parsed for your domain, and the matching anchor is clicked — including pagination when the target sits deeper.

  • SERP anchor detection with redirect unwrapping
  • Page traversal when the result isn’t on page one
  • Works across Google, Bing, Yahoo and DuckDuckGo
› mode: Google · keyword: "best seo tools" · count: 10

Proxy-mediated search

Search traffic routed through a dedicated proxy node, keeping the search engine, the SERP click and the landing page all on the same egress IP for a coherent session story.

  • Consistent IP from query to landing page
  • Useful for geo-sensitive ranking checks
  • Pair it with headless mode for long batches

Pipeline

From config to report in eight steps

The runner is a linear pipeline with a single guard: only one campaign executes at a time, so sessions never interfere with each other.

01Load config

URLs, keywords, proxies, emails, comments and timing are read from disk.

02Pick a proxy

The next node in the pool is assigned to this session index.

03Launch browser

Chrome starts with stealth flags, proxy config and a rotated profile.

04Navigate

Direct URL or search keyword, typed at a human cadence.

05Simulate

Scroll, dwell, click-through and optional like / comment actions.

06Log the session

Proxy, identity, mode and outcome are written to the console.

07Rotate

Browser closes, index advances, pause delay applies, next session begins.

08Report

Telegram receives a start card, then a done or error summary.

Get started

Running in three minutes

You need Node.js 18+, Google Chrome and a proxy list. Telegram is optional but recommended if you want remote control.

  1. 1
    Clone the repository

    Or download the latest release archive.

  2. 2
    Install dependencies

    Electron, Selenium WebDriver and ChromeDriver are pulled in.

  3. 3
    Drop your proxies

    One per line in proxy/ — HTTP, HTTPS or SOCKS5.

  4. 4
    Launch the app

    Add a URL, choose a mode, press Start.

  5. 5
    Optional · Telegram

    Copy the example config, add your token and chat IDs.

# 1 — clone and install
git clone https://github.com/zougar99/traffic-bot.git
cd traffic-bot
npm install

# 2 — launch the desktop app
npm start

# 3 — optional: verify Telegram wiring
npm run test:telegram

Questions

Before you install

What is this actually for?
Validating analytics, testing SEO assumptions and load-checking tracking on sites you own or are authorized to test. It is a lab instrument — treat it like one.
Do I need a server or cloud account?
No. It’s a desktop app. Everything — proxies, keywords, comment and email libraries — lives in local folders inside the project.
How many proxies do I need?
Five to ten healthy nodes is a sane start for small batches. For thousands of sessions a day, a larger residential pool with rotation is strongly recommended.
Does headless mode work?
Yes. Toggle “Headless” and Chrome runs invisibly — better throughput for long batches. Keep it off when you’re debugging a flow, so you can watch what happens.
What happens if a proxy fails?
The session fails, the error is logged, and the runner continues with the next session index — which maps to a different proxy in the pool. One dead node never halts a campaign.
Which search engines are supported?
Google, Bing, Yahoo and DuckDuckGo are wired in. Yandex and Baidu are on the roadmap.
Is Telegram required?
No — the desktop UI works on its own. Telegram adds remote /run control and run reports when you’re away from the machine.
Is it free?
The source is MIT-licensed and free to use. You provide your own proxies, which are the only real running cost.
