Capabilities

Everything a traffic test needs — and nothing hidden

Nine moving parts, one readable runner. Each layer is configurable, observable and swappable without touching the others.

Proxy pool with per-session rotation

Drop any number of files in proxy/. The runner assigns pool[i % n] to every session, so no node carries two visits in a row.

Stealth, without the snake oil

Navigator patches, WebGL / Canvas / Audio fingerprint spoofing and randomised Chrome launch flags. No daemon, no external service — all in libs/spoofing.js.

Human cadence

Typing delays, smooth scroll intervals (700–1400 ms), dwell time before engagement.

Search journeys

Keyword → SERP → your result, with pagination when you rank on page two.

Engagement

Optional like + comment, with a comment library and rotating identities.

Remote control from Telegram

Start, stop and inspect a campaign from your phone. Reports arrive as start, checkpoint and summary cards.

local-first

One machine, zero tenancy

No SaaS, no shared dashboard, no usage metering. Your proxies, keywords and comments never leave ~/traffic-bot.

Batch queues

Many URLs × N sessions, interleaved in rounds so traffic spreads over time.

Live console

Every session prints mode, proxy, identity and outcome — nothing is a black box.

Headless or visible

Watch the browsers, or run quietly at full speed in the background.

Operating modes

Three paths to the same page

Each mode has its own session flow and timing. Pick the one that matches the signal you are validating.

Direct navigation

The cleanest signal for analytics and tracking validation: one proxy, one browser, one page view with realistic dwell and scroll.

  1. 1Assign proxy — next node from the pool, credentials normalised to a URL Chrome accepts
  2. 2Open Chrome — stealth flags, headless if requested, fresh profile
  3. 3Land & wait — delay after load, then smooth scroll
  4. 4Engage (optional) — like / comment with a rotating identity
› mode Direct · url https://your-site.com · sessions 25

Search-engine journey

The organic path: type the keyword, parse the SERP, find your domain and click the result — with pagination when you are not on page one.

  1. 1Query — keyword typed into Google with human delays
  2. 2Parse — anchors extracted and redirects unwrapped to real URLs
  3. 3Match — hostname + path prefix compared against your target
  4. 4Click through — result clicked, then dwell and engagement
› mode Google · keyword "best seo tools" · sessions 10

Proxy-mediated search

A third-party browsing service fetches the SERP, then the bot clicks your result. Useful when the search engine and the landing page must share one egress identity.

  1. 1Route — the assigned proxy is applied to the whole browser
  2. 2Search remotely — keyword submitted through the service
  3. 3Locate — your domain is found in the returned page
  4. 4Click & dwell — then optional engagement
› mode Proxy · keyword "saas analytics" · sessions 15
Anatomy of a session

Five stages, fully timed

Every session goes through the same five stages. Each one has its own delay, so you can tune realism against throughput without editing code.

01RotateNext proxy from the pool is bound to this session index.
02LaunchChrome starts with stealth flags and a clean profile.
03NavigateDirect URL, or a keyword typed into a search engine.
04DwellDelay after load, smooth scroll, optional engagement.
05ReportClose browser, log the outcome, notify Telegram.

Remote control

Your campaign, in a chat window

Add a bot token and the app becomes controllable from your phone. Useful for long batches you don't want to babysit at the desk.

  • /run — start a campaign with mode, count and keyword
  • /stop — abort the active run cleanly
  • /status and /myid — pool size and chat identity
  • Allow-list only — commands ignored unless the chat id is whitelisted

Get started

Three minutes to first session

Node 18+, Google Chrome, and a proxy list. Telegram is optional; so is headless mode.

  1. 1
    Clone the repo

    Or grab the latest release archive.

  2. 2
    npm install

    Brings Electron, Selenium and ChromeDriver.

  3. 3
    Add proxies

    One per line in proxy/ — host:port, user:pass@host:port, http:// or socks5://

  4. 4
    npm start

    Paste a URL, choose a mode, press Start.

  5. 5
    Optional: Telegram

    Copy the example config, add your token and chat id.

Questions

Before you install

What is this actually for?
Validating analytics, testing SEO assumptions and checking tracking on sites you own or are authorised to test. It is an instrument, not a growth trick — treat it that way.
Do I need a server or a cloud account?
No. It is a desktop app. Proxies, keywords, comment libraries and email identities all live in local folders inside the project.
How many proxies should I start with?
Five to ten healthy nodes is a sane start for small batches. Thousands of sessions a day need a larger pool, ideally residential, with rotation.
Does headless mode work?
Yes, and it is faster. Keep it off while debugging a flow so you can watch Chrome do the work.
What happens when a proxy dies mid-campaign?
That session fails and is logged; the next session index maps to the next node. One dead proxy never halts a run.
Is Telegram required?
No. The desktop UI stands alone; Telegram only adds remote commands and run reports.
Is it free?
Source is MIT. Your only running cost is the proxy pool you choose to use.
Is this legal?
It is built for testing properties you own or are authorised to test. You are responsible for complying with the terms of service of any site you interact with.
